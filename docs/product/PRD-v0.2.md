# LUMET — PRD v0.2

- 상태: Draft · 2026-10-03 (KST)
- 제품 유형: 모바일 우선 개발자 학습 PWA
- 브랜드: Lumet(가칭), 정식 출시 전 이름 사용 가능 여부 확인 필요
- 한 문장: 개발자가 원하는 기술을 선택해 코드를 읽고, 실행 흐름을 관찰하고, AI가 만든 코드를 스스로 검증하도록 돕는다.

## 1. 사용자와 해결 문제

**주요 사용자:** 2년 이상 개발 경험이 있거나 현업 코드를 읽는 개발자. 새로운 언어·프레임워크를 배우거나 AI 생성 코드를 리뷰해야 하는 사람. 경력 연수는 강제 가입 조건이 아님.

**JTBD:** “익숙하지 않은 코드가 어떤 상태 변화와 부작용을 낳는지 짧은 시간 안에 이해하고, 문제를 찾고, 변경 결과를 예측하고 싶다.”

**회피할 제품 형태:** 강의를 무작정 나열하는 카탈로그, 퀴즈 정답만 맞히는 게임, 자동 리뷰 결과를 무비판적으로 전달하는 서비스.

## 2. 제품 원칙

1. **Stack-agnostic discovery:** 기술을 먼저 고르게 하고, 기술별 제공 범위·콘텐츠 준비 상태를 투명하게 표시한다.
2. **Visual first:** 코드 줄과 상태 변화, 호출 경로를 연결한다.
3. **Reviewer agency:** 먼저 예측·선택·근거 작성, 그다음 결과·해설 제공.
4. **Mobile-first, desktop-capable:** 모바일은 이해·리뷰, 데스크톱은 더 복잡한 작성·검증.
5. **Verified explanations:** 시뮬레이션과 실제 실행 결과에 출처·버전·가정을 붙인다.
6. **Theme parity:** 기본은 OS 설정을 따르는 다크·라이트 모드를 제공하고 수동 전환을 기억한다.
7. **Free complete loop:** 무료로 선택→읽기→추적→리뷰→해설 전체를 경험할 수 있다.

## 3. P0: 첫 프로토타입

| ID | 요구사항 | 수용 조건 |
|---|---|---|
| P0-01 | 시작 화면 | 서비스 가치와 학습 시작 경로가 1화면에서 파악 가능 |
| P0-02 | 기술 탐색 | 기술 검색·복수 선택, 미지원 기술 관심 표시 가능 |
| P0-03 | 샘플 레슨 | 최소 2개 서로 다른 언어의 검증된 사례, 언어·버전·전제 표시 |
| P0-04 | 코드 읽기 | 모바일에서 줄 번호·강조 줄·가로 스크롤이 자연스럽게 동작 |
| P0-05 | 단계 재생 | 이전/다음/자동 재생/일시정지/속도 선택, 현재 단계 표시 |
| P0-06 | 상태 표시 | 단계마다 코드 줄·변수 값·설명이 동기화되어 표시 |
| P0-07 | 리뷰 챌린지 | 결과 예측 또는 문제 식별→제출→근거 해설 흐름 |
| P0-08 | 진실성 | 모든 샘플에 '검증된 학습 시나리오 · 실제 코드 실행 아님' 표시 |
| P0-09 | 접근성 | 터치 타깃 최소 44px 목표, 키보드 접근성, 포커스 표시, reduced-motion 대응 |
| P0-11 | UI 테마 | 다크·라이트 전환과 선택 유지, 두 테마 모두 코드 가독성 확보 |
| P0-10 | 기본 통계 | 동의 기반으로 온보딩 선택·레슨 시작·추적 완료·리뷰 제출 집계 설계(프로토타입은 서버 전송 없음) |

**프로토타입의 범위:** 정적 JSON/JS 시나리오 기반 인터랙티브 UI. 실제 실행기, AI API 호출, 소셜 로그인, 서버, 결제 및 GitHub OAuth는 포함하지 않는다.

## 4. P1: 공개 베타

- React + TypeScript + Vite 기반 구현 및 PWA 설치 요건(매니페스트, 아이콘, HTTPS, 캐시 정책) 검증.
- 사용자 계정 없이도 무료 학습 가능. 동의 시 진도 동기화용 계정 제공.
- Spring Boot + PostgreSQL으로 콘텐츠·선호 스택·학습 상태 관리.
- 콘텐츠 제작 파이프라인: 시나리오 스키마 검증, 런타임/문서 기준 교차 검증, 리뷰 승인.
- 미지원 스택 요청 수집. 각 기술의 제공 상태를 `available`, `preview`, `planned`로 표시.
- 사용자 인터뷰 및 학습 전후 문제 수행 평가.

## 5. P2: 고급 기능 (검증 후)

- 사용자 코드 붙여넣기 → 언어 인식 → 지원 환경에서 격리 실행 및 실제 trace 수집.
- GitHub App 또는 최소 권한 OAuth로 명시적으로 선택한 파일/PR만 분석; 비공개 저장소는 저장 기본값 OFF.
- AI 설명·추가 질문·개인 맞춤형 과제. AI 설명은 실제 trace와 분리 표시.
- 데스크톱 코드 수정, 브레이크포인트, 비교 trace 및 리포트.
- 선택형 소액 유료 기능: 고급 콘텐츠 팩·고비용 분석량·복습 도구.

## 6. 첫 사용자 흐름

`홈 → 스택 선택 → 관심 기술/주제 선택 → 코드 읽기·결과 예측 → 단계별 Trace → 리뷰 제출 → 근거 해설 → 다음 학습`

미지원 기술은 강제로 다른 언어에 연결하지 않는다. 대신 미지원 상태, 관심 등록, 사용 가능한 인접 콘텐츠를 표시한다.

## 7. 검증할 가설과 지표

- 가설 A: 실제 개발자는 코드 생성보다 실행 이유를 이해하고 직접 리뷰하는 기능에 재방문한다.
- 가설 B: 모바일 5~10분짜리 Trace+Review 한 사이클을 완료할 수 있다.
- 가설 C: 사용자는 자신의 기술을 자유롭게 고르는 온보딩을 선호한다.
- 가설 D: 무료 학습 만족 이후 특정 고급 기능에 기꺼이 결제한다.

**계측:** 코스 진입률, 첫 trace 완료율, 첫 리뷰 제출률, D1/D7 재방문율, 학습 전후 유사 문제 정답률, 지원 요청 기술 분포, 1회 분석 추정 원가, 유료 전환율. 숫자 목표는 베타의 실제 기준치를 확인한 뒤 설정. 소수 인터뷰 결과를 시장 전체의 수요로 일반화하지 않는다.

## 8. 주요 위험

- 기술별 실행 모델을 하나로 과도하게 일반화하면 교육적으로 틀린 그림을 제공할 수 있음.
- 'AI가 코드에서 실제로 발생한 현상'과 'AI가 추정한 동작'을 구분해야 함.
- 사용자의 코드에는 비밀키·개인정보·회사 기밀이 포함될 수 있음.
- 복잡한 샌드박스, 네트워크 접근, 결제 기능은 MVP 범위 밖.
- Lumet은 현재 다른 웹/기술 서비스에서 사용 중이며, 국내 상표 등록과 유사상표 충돌 여부는 미확정. 브랜드는 가칭.

## 9. 완료 정의

휴대전화 화면에서 최소 2개 언어 샘플을 선택해 직접 실행 단계를 진행하고, 정답 제출 및 해설 확인이 가능할 것. 모든 단계·가정이 문서화되고 테스트가 통과하며 5명 이상에게 조작·이해 가능성 피드백을 받을 수 있을 것. 실사용 검증 결과와 코드는 별개 산출물로 기록한다.
